# Changelog

Newest first. One line per change that a user or the team would notice.

## October 2026

- Table rows that open something now look clickable. On hover the row takes a clear green tint and a green bar at its left edge, and the pointer is a hand (before, only a barely visible grey tint). On the Dashboard's Work queue and "Due this week", the Requests list, the Clients table, the client page's open requests and documents, and the request page's client and document rows. One shared style (`lib/ui.ts`).
- Dashboard, switching the Work queue tab (All / To review / Waiting) no longer makes "Due this week" flash: its rows were falling back to their start state (invisible, 8px down) on each re-render and fading in again. They no longer animate in on a re-render; the calendar and the greeting were already steady.
- Dashboard, the Work queue no longer has checkboxes or a bulk bar. A "select all" could only mean the few rows on screen, and the one bulk action (a reminder) is a button on each waiting row anyway. The first column is gone, so the client column starts at the left edge and the header lines up with the rows.
- Dashboard, the amber strip about files waiting in the Inbox was tried and taken out (it did not fit the page). Files not placed yet are shown only in the Inbox.
- **Approving a document now asks where to keep it in Document Master** (before, every approved document was filed in its client's folder by itself). In all three places where a document is approved (the Inbox preview, the request page's side drawer, and the status list on the request page) **Approve** opens the Save-as folder window with the folder we would suggest already chosen (the client, then the year, then the kind of work, e.g. Ramesh Kumar › FY 2025-26 › ITR; or the folder the CA used for it before). Three ways out, none hidden: **Approve and save here**, **Approve without saving**, or **Cancel** (nothing is approved). The window below lists the file's name, and "and N more files" for a document of several files (all of them are saved). The preview or drawer under it hides while the window is open. On the request page, after answering, the drawer goes on to the next document, and the last toast says both things ("… approved and saved in Document Master. All done. Nothing left to review").
- Approved documents show where they are kept: in the Inbox preview, under Reject/Approve, a line "Ramesh Kumar › FY 2025-26 › ITR" with **Change**, or "Not saved in a folder yet" with **Save…** (the same folder window), so a document approved without saving can be filed later.
- Document Master: an approved document that is in no folder (approved without saving) sits at the top level ("All folders", under the heading "Not in a folder yet"), and a line at the top of the left list, "N approved files are not in a folder yet · Show", says how many so they are not forgotten. A document of several files shows as several files. The sample documents approved before this was asked stay in their client's folder.
- Document Master, deleting a folder the CA made no longer deletes the approved documents saved in it. They belong to the request, so they just lose their folder and go to "Not in a folder yet"; the delete window says so ("The 1 approved document in it is not deleted…"). Files uploaded by the CA in that folder are still deleted, as before.
- Inbox side panel, the request cards are redesigned with each part earning its place. The card starts with a very light band that opens the request: the **checklist's name** in green semi-bold (colour and weight make it stand out, not a big size), the request number in plain muted text (no pill) and a small arrow. No kind tag (GST / ITR / TDS): it is already in the name. **The client is not repeated** when the chat is one client's, since the chat header says it. It appears only where it tells cards apart: the client's name (with a small avatar) when the chat has several clients (Ram and Reeta Sharma), and the place (Maharashtra, Karnataka) when a client has several GSTINs or TANs. Below the band: the progress and the checklist. The "Open request" link at the bottom is gone, since the band is the link.
- Request page, files that are on no document ("Not placed") are no longer shown here. They are not part of a request (they belong to the client's WhatsApp number, so they used to appear in every request of that client, which was confusing when a client has more than one). Gone: the "Not placed" rows among the checklist, the "+ N to place" line and the "N to place" chip in the client's row, and the side drawer that opened for them. A client row's chip is now only "N to review", "Overdue", "Waiting" or "Done". Such files are dealt with in one place only: the Inbox (the chat's "N files not placed yet" list). Also removed the old unused picker inside the preview drawer.
- Inbox, the note under a placed file in the chat now follows the document. It used to be fixed text from the moment the file arrived ("Placed on GSTR-2B · Karnataka · To review"), so after the CA approved it the checklist showed a green tick but the chat still said "To review". The last word is now read from the document itself (To review, Approved or Rejected). Moving a file also updates the chat: the note names the new item; in a swap both files' notes change; and taking a file off the checklist turns its note back to "Not placed yet" and returns all the files of that document (not only the open one) to the waiting list.
- Inbox, Save-as folder window: every folder row now has a number at its right, the count of files in it (counting the folders inside it): for example Firm documents 13, Registrations 4, and each client's number. When there is nothing to guess the client from (a number we do not know), the window opens with "Firm documents" and the "Client list (N)" already open, so the user can see and choose; when the client is known, the client list stays closed so a file is not saved in the wrong client by a slip.
- Documents, a new document no longer starts with a category chosen for the user (it was the category open on the page). The Category box comes first (above the name) and says "Choose a category"; the user must pick one; "Add document" stays off until a name and a category are given. Editing an existing document keeps its category.
- Documents, a document can **allow more than one file** (a checkbox "Allow more than one file" in New document and Edit document; a small "Several files" tag on the row). Only then can a second file be added to it. Aadhaar, salary slips, rent receipts, bank statements, FD and loan statements, health insurance, 80G, tuition fees and LIC receipts start with it on; every other document, and any new one, starts with it off. The rule is copied into each request when it is made. **A one-file document:** a new file from the Inbox takes the place of the old one (the Add-to-a-request window lists it under "Already has a file: this file will replace it"; the request page's list says "Replace the file of"). **A several-files document:** the new file is added to it ("Already received: this file will be added as another file of it"). On the client's upload page, a one-file document takes one file (the file box does not accept several and there is no "Add another"), and a several-files document takes many. The preview's file chips only show when a document has more than one file.
- Inbox file preview, the header uses its space: under the file name it says "<client> · came by WhatsApp chat · Today, 10:42 · size" (and "file 2 of 3"), so the right side starts straight with the checklist (it no longer repeats the client's name and how it came). The bar with the file chips shows only when a document has more than one file; there is no "Add file" button.
- Inbox file preview, the checklist now has one highlight at a time. Clicking the picked item again, or this file's own item, undoes the pick. "None of these" is highlighted the same way.
