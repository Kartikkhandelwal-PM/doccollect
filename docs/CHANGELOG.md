# Changelog

Newest first. One line per change that a user or the team would notice.

## October 2026

- Client page, Requests tab: the filter row is tidy. All three dropdowns (Module, Registration, Status) use one shared component with the same height, width and arrow position, and a clear focus ring. The Registration dropdown shows only the place on its button (Maharashtra, Karnataka), and when opened each choice has the place on top and the GSTIN / TAN / PAN small and grey under it; the search box has a fixed, modest width.
- Client page, Requests tab, repeats removed: the Registration column shows the badge (GST) and only the place (Maharashtra), not "GST · Maharashtra"; the module is a dropdown in the filter row, like Registration and Status (All modules, GST, TDS, ITR, each with its count) instead of pills or tabs;  the line "Showing X of Y requests" above the table shows only when a filter is on (the table footer already says it).
- Client page, Registrations tree: the client card on the left is the picture of the whole client, with only what is not said elsewhere on the page. A small CLIENT label, the name, Business or Individual, the PAN, mobile and email, and three numbers: registrations, contacts (people who get messages) and open requests (orange when above zero). Under the name, a short block with the PAN, the main contact's mobile and email. A kind with one registration no longer shows its own "N open" pill, since its card says it.
- Client page, Registrations tree, with nothing repeated: the summary strip and the hint line are gone (the tab count and the header already say it), the client card is only the name (the avatar and the PAN are in the header), the status dot is gone (the pill says it), "N open" shows only when something is open (no "All clear"), and there is no MAIN tag. Cards are wide, one per row: the place and number on one line, the contact's name and mobile on the second (no avatar).
- Client page, Registrations tree: the client tile on the left is now a proper card with details. A colour strip on top, a big avatar, the name and whether it is a Business or an Individual, the PAN, the main contact (name, mobile, email), and a footer with the kinds the client has (ITR, GST, TDS, with a number when more than one) and where the client came from (KDK sync).
- Client page, Registrations tree, tidied: the tree sits in one card with a summary strip on top (registrations, contacts, open requests, and a key to the three colours) and the hint below. The client card is compact and on one line (avatar, name, PAN). Every Income tax / GST / TDS node is the same size, and every registration card is the same size: the place and number with "N open" or "All clear" on top, and the contact under a dashed line (always the person's avatar and name, with a small MAIN tag when that person is the client's main contact; "Main contact" is no longer written in place of a name). Lines are thinner with rounder elbows and the spacing is even.
- New request, step 1 now looks and works like the Checklists page. Left: a search, All / Income tax / GST / TDS buttons with counts, the list of checklists (badge, name, number of documents) and "Make my own checklist" fixed at the bottom. Right: a coloured header with the badge, the name and "GST · 4 documents · sent to each GSTIN"; below it two columns that scroll on their own, "All documents" (search, tick to add, or type a new name to make one) and "In this request" (numbered, each with a remove button, Clear all). If the CA changed the documents, "Reset to 4 saved" shows in the header. "Make my own checklist" turns the header into a name box with the Used for buttons and "Keep for next time". Picking another checklist after changing documents still asks first.
- New request, step 1: the Checklist dropdown is a custom dropdown exactly as wide as its field (it used to open as wide as the whole page), with the checklists in groups (Income tax, GST, TDS), a tick on the current one, and at the bottom "Make my own checklist". Choosing that shows a Name box (this is also the name of the request and what the client sees in the message), the "Used for" choice, and a tick "Keep it in Checklists for next time" (on by default; the checklist is saved when the request is sent). The chosen documents box has a maximum height and scrolls inside when 20 or more are chosen, so the list below never gets pushed away.
- New request, step 1, the top box is a proper two-column grid: on the left the Checklist dropdown (with a GST / TDS / ITR note under it, or the Used for choice for "Start from scratch"), a thin line, and on the right the Documents (count, Clear all, chips). When the CA has changed the documents, a small "You changed the documents. Reset to 4 saved" appears under the dropdown.
- New request, step 1, tidied: the Checklist dropdown has a fixed, sensible width, with a small "GST · Sent to each GSTIN" note beside it; the Documents list no longer sits in its own inner box, so everything lines up on one left edge; every card has the same padding; each group of documents shows how many are added ("GST · 3 of 22 added").
- New request: the screen is used for the work. The side panel (summary and message preview) is gone from steps 1 and 2; both use the full width, with no repeated headings. Step 1 is just the Checklist dropdown and the Documents box. Step 2 is a full-width table: Client (with the place), GSTIN / TAN / PAN, Contact, Mobile, and a WhatsApp off tag, with Select all and "3 of 115 selected"; it is as tall as the screen allows and scrolls inside. The footer says what is being sent ("GST monthly · 3 selected"). Step 3 has Send from, Last date and the short summary on the left, and the message preview on the right.
- Request page: the green Review button on each client row is gone. A client row now shows only a Remind button when something is still pending (even if some files wait for review), a Send update button when everything is approved, and no button when all files are in and only the review is left. To review, open the row and click a document (or its TO REVIEW tag).
- Request page, an opened client: its actions are two small buttons inside the same highlighted tile, right under the client: Open chat (goes to that client's chat in the Inbox) and Send a new link (a fresh link goes to the client on WhatsApp and the old one stops working). "See what the client sees" and "Copy link" were taken out. The documents follow below.
- New request, step 1: one "Checklist" dropdown (Income tax, GST and TDS checklists in groups, plus "Start from scratch"; the checklist decides what the request is used for). Under it a "Documents" box with the checklist's documents as chips (each with a remove button, and Clear all), and below that an "Add documents" box that is always open: every document as a pill, in groups (GST or TDS first), with a search on the right. Documents already in the list are shown ticked; click a pill to add it or take it away. A new name typed in the search offers "Add 'name' as a new document". There is no popup any more. If the CA has changed the documents and then picks another checklist, a question asks first. "Start from scratch" shows a small Income tax / GST / TDS choice.
- Wording: one word for documents not received yet: "pending" (the PENDING tag on a document, "N pending" under a client's status, "N documents pending" on the Dashboard). The word "missing" is no longer used for this.
- Request page: the "..." button on every row is gone, and the three action buttons (Review, Remind, Send update) are now the same size. The link actions (See what the client sees, Copy link, Send a new link) are three small text links on one line at the top of an opened row, with a red "The upload link has expired" on the left when it applies. The top "Review N documents" button was removed: review is done from each client's own Review button.
- Request page: "Link valid till ... · Open client" is gone. The client's name in the row is now the link to the client page (it does not open or close the row). "Link expired" is still shown when it applies.
- Request page, opened row: less noise. The extra line (number, place, "Messages go to") is gone, since the row already shows the number and the contact. Pending documents no longer say "Not received yet" under the name (the PENDING tag says it). The "Files we could not match" heading and its note are gone: those files sit in the list with a NOT PLACED tag, and opening one lets the CA choose its document. An opened row now shows the link line and the documents.
- Request page: the GST / TDS / ITR label is no longer repeated on every client row, because the title badge already says it. A row shows only the place (for example Maharashtra) when the client has several GSTINs or TANs. If one request mixes kinds, the label stays on the rows.
- Request page: a new Contact column in the table shows who gets the messages for each row (the registration's contact, name and mobile). The client column now shows the registration number under the name.
- Request page: the title shows a badge (GST, TDS or ITR). Each client row now shows the registration number under the name (GSTIN for GST, TAN for TDS, PAN for income tax) next to the mobile. An opened row starts with a line: the number, the place, and "Messages go to" the contact and mobile. The client's upload page also shows that number under "Hi <name>", so a client with several GSTINs knows which one the request is for.
- Documents: when a document sits in checklists, the CA is asked before changing it. Delete says "Delete 'PAN card' from 10 checklists?", names the checklists (first four, then "and N more") and the button says "Delete from 10". Renaming such a document first asks "Change the name in 10 checklists?" and shows old and new name; changing only the category does not ask. A document that is in no checklist is deleted or renamed without extra questions. Requests already sent and files already received are never changed.
- "Documents list" is now **Documents** (menu and page). Layout kept (categories on the left, documents on the right), cleaned up: a "New document" button in the header opens a small window (name and category) instead of an input in the list; each row shows its name and how many checklists use it ("Not used" when none), with a "..." menu for Edit (same window) and Delete (asks first, and says how many checklists it will leave); in "All documents" and in search a Category column is shown; an empty category offers "New document".
- Checklists, top of the right side redone: a coloured badge (ITR, GST or TDS), a soft tint, the name as a plain title with "Income tax · 7 documents" under it. Editing is in the "..." menu: a Name box, a "Used for" dropdown (Income tax, GST, TDS), and Delete checklist (which asks first).
- Wording: the word "Kind" is gone from the screens. A checklist now says "Used for" (Income tax, GST or TDS). Everywhere else only the three names are shown: "Income tax", "GST", "TDS" in buttons and filters, and the small ITR / GST / TDS badges on rows.
- Checklists page: one page, three clear parts. Left: search, All / Income tax / GST / TDS buttons with counts, and the list of checklists (kind badge, name, number of documents). Right, top: the name as a title (turns into a box when you point at it), the kind next to it, and a "..." menu. Delete is in that menu and asks a clear question first (requests already sent are not changed). Right, below: two columns that each scroll on their own. "All documents" (a search that stays in place, tick to add, or type a new name and press Add to make a new document and add it) and "In this checklist" (a numbered list with a remove button on each row and Clear all). No more chips that push the search down.
- Checklists have a kind again (Income tax, GST or TDS), picked when the checklist is made (Setup > Checklists). Without it a GST checklist could be sent to a TDS registration. New request step 1 starts with an Income tax / GST / TDS bar, then only the checklists of that kind; step 2 lists only the registrations of that kind. "Income tax" covers everything filed on the PAN (ROC, KYC and the like).
- "Compliances" is now **Checklists** (Setup menu, page title, buttons, messages). A compliance means a filing to a CA; this page holds saved lists of documents. The old address /compliances still works and goes to /checklists.
- New request, step 1 redone: the list of documents is always open (no "Add or change" button). Chosen documents are chips at the top (with Clear all). Below, a full-width list of all documents in columns, with a search box: tick to add, untick to remove, or type a new name and press Add. The group of the chosen kind (GST or TDS) comes first.
- More starter checklists: GST now has 9 (monthly, quarterly QRMP, GSTR-1, GSTR-3B, annual, audit GSTR-9C, refund, export and LUT, notice reply, amendment or cancellation, registration) and TDS has 9 (quarterly, salary 24Q, contractors and professionals 26Q, rent, non-resident 27Q, return correction, notice reply, salary declarations, TAN registration). More GST and TDS documents were added to the Documents list too.
- New request, Who to ask: no "Already asked" tag and no filter. It could not tell a changed set of documents or another month from a repeat. Each row shows its client, number, the contact's name and mobile, and a "WhatsApp off" tag when no message can go. A duplicate check can come back later, together with a period.
- New request has three steps, in a new order. 1) What you need: pick Income tax, GST or TDS, then a checklist of that kind (documents come filled in as chips you can remove; "Add or change documents" opens the full list; or "Start from scratch"). 2) Who to ask: only registrations of that kind, one row each, with search and "Select all". 3) Review and send: send from, last date, one Send button. A summary and message preview stay on the right through all steps; it warns when a registration already has the same request open, and when WhatsApp is off. From a client page it opens at step 2 with the client's registrations picked.
- Compliances now have a kind (Income tax, GST or TDS), set in Setup > Compliances. Everything filed on the PAN (ROC, LLP, PF/ESI, bookkeeping, KYC and the like) is Income tax. No "Other". New starter checklist: KYC documents.
- Client page, Registrations: drawn as a tree, like Compliance Tracker's Structure view. Client on the left (name, PAN, registrations and contacts), then Income tax / GST / TDS (one colour each for the node and its lines; a kind the client does not have is a dashed card), then each GSTIN or TAN as a card: place, "N open" when something is open, number, and its contact ("Main contact" when it is the client's own, as in Compliance Tracker; otherwise the person's name). Clicking a registration opens a side panel (contact, Change contact, WhatsApp / Email switches, open requests). On a phone the tree reads top to bottom. Replaces the earlier tiles; no view toggle.
- Client page, Requests: kind chips with counts, a Registration dropdown (replaces the separate chip that did not match the dropdown), status, search, and "Showing X of Y requests · Clear filters". The whole row opens the request.
- Client page: the Compliance Tracker style tabs and the redesigned Registrations table were taken back. It is the single Registrations tab again (one table, one line per registration).
- Change contact: Edit now opens its own view (back arrow, "Edit contact", labelled Name / Mobile / Email, a short "Applies to N registrations" line when it is more than one, Save changes). The list and "Add a new contact" step aside, so Add and Edit are clearly separate.
- Inbox, Unassigned: tap the unsaved number at the top of the chat to "Save contact": give it a name and pick the client (list shows name and PAN, search by either, the client we guessed from the files is marked Suggested). The number is added as one more contact of the client (their own number stays), the chat becomes that client's chat, and files still waiting move to "files that need a place". Each file in Unassigned can also be saved on its own, with its own client / registration choice.
- Inbox: files that arrive on WhatsApp are "read" (what it is, whose it is, PAN or account number), even when we did not ask for them. In Unassigned, each file shows what we read and a guess of the client (by PAN, else by name) with a one-click "Save for client". Several PANs or bank statements in one go are each read and matched on their own. Same document sent twice is marked a duplicate. Not sure? It stays in Unassigned for staff; the client is not messaged. The reading is made up for now (demo); real OCR / AI comes with the backend.
- Overview: the Details card was removed (name, PAN and counts are already in the header and tabs).
- Main contact card on the Overview has a Change button (pick, add or edit). Registrations without their own contact follow the main contact. "N other contacts" button removed.
- Overview shows only the main contact, not the whole contact list (a client can have many). Other contacts are in Registrations.
- Client page: clicking the GST / TDS / Income tax card opens Registrations with that kind selected. Open / overdue counts on it are plain text. Requests has a status filter.
- Contacts per registration: sample clients now have different contacts on different GSTINs/TANs (Priya Textiles has a third GSTIN, Rajasthan). Change contact lists the client's contacts with what each handles, lets you add a new one, and Edit one for every registration that uses it.
- Client page rebuilt with four tabs (Overview, Registrations, Requests, Documents). Registrations and Requests are paged tables that work for 50 GSTINs. Per registration: contact with Change, WhatsApp and email switch. No tree view. Messages and Activity tabs removed (Open chat button stays). Request messages respect the contact and the WhatsApp switch.

- Clients: All / GST / TDS / ITR is now a dropdown. Registration counts read "GST (2)". Sample: Anand Traders has two TANs.
